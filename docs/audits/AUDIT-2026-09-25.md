## Hallazgos críticos

### COC-SEC-001 — Sin autenticación/autorización server-side en rutas administrativas
CRÍTICA. PUT /api/recipes/:id/status modifica estados sin autenticación. GET /api/admin/metrics tampoco exige autenticación. El frontend usa isAdmin como estado local y permite alternarlo.
Impacto: cualquier cliente puede intentar aprobar/rechazar/ocultar contenido y consultar métricas/reportes.
Corrección: Firebase Authentication + middleware server-side + Custom Claim admin === true.

### COC-SEC-002 — Importación pública y autoaprobación controlada por cliente
CRÍTICA. POST /api/collector/import no requiere autenticación y acepta autoApprove desde el body; puede crear ACTIVE.
Corrección: endpoint solo admin; quitar autoApprove del cliente; toda importación debe quedar en PENDING_REVIEW/DRAFT.

### COC-DATA-001 — Persistencia completamente en memoria
CRÍTICA. recipesStore, reportsStore y recentSearchesStore son arrays locales.
Impacto: un reinicio pierde catálogo/reportes/analítica y varias instancias tendrían datos distintos.
Corrección: Firestore como fuente persistente, con paginación e índices.

### COC-SEC-003 — SSRF mediante WebsiteConnector
CRÍTICA. WebsiteConnector acepta cualquier HTTP/HTTPS y el servidor hace fetch de la URL recibida.
Corrección: allowlist estricta de hosts/plataformas, HTTPS, bloqueo de loopback/privadas/link-local y sin fetch arbitrario.

### COC-SEC-004 — Embed URL arbitraria
ALTA. WebsiteConnector y ManualConnector pueden usar la URL recibida como embedUrl.
Corrección: generar embeds solo desde proveedores/hosts permitidos y validar nuevamente en servidor.

### COC-SEC-005 — Reportes públicos sin autenticación/rate limiting
ALTA. POST /api/reports puede ser invocado sin identidad ni límites.
Impacto: spam y manipulación de Quality Score.

### COC-SEC-006 — Falta hardening HTTP
ALTA. No se observa CORS allowlist, body limit, security headers ni rate limiting global.

## Otros hallazgos

### COC-DATA-002 — Estados internos expuestos
GET /api/recipes acepta status y permite consultar estados distintos de ACTIVE.

### COC-DATA-003 — Detalle público sin filtro de estado
GET /api/recipes/:id devuelve cualquier receta encontrada, independientemente de su estado.

### COC-API-001 — Vistas manipulables
GET de detalle incrementa viewsInternal sin rate limiting.

### COC-API-002 — Métricas y reportes sin paginación
El endpoint administrativo devuelve arrays completos y calcula métricas en memoria.

### COC-AI-001 — Prompt injection/datos no confiables
Metadata externa se interpola directamente en prompts de Gemini. Semantic search además envía todo el catálogo al modelo.
Corrección: limitar/truncar entradas, separar datos de instrucciones y no enviar todo el catálogo.

### COC-AI-002 — Gemini sin controles de coste
Importaciones y búsquedas IA no tienen rate limit, cache ni cuota propia.

### COC-DATA-004 — Metadata ficticia
CRÍTICA. YouTubeConnector usa fallbacks como ID dQw4w9WgXcQ, duración 15:30, 125000 vistas, fecha actual y descripción genérica cuando falla la metadata.
Impacto: un enlace puede convertirse en una receta falsa.
Corrección: fail-closed; sin metadata verificable, no importar.

### COC-DATA-005 — Datos derivados frágiles/inventados
IDs basados en Date.now pueden colisionar; prepTimeMinutes usa parseInt de texto libre; servings se fija en 4.

### COC-SEC-007 — Validación YouTube débil
La regex no valida hostname mediante URL ni exige esquema/host exactos.

### COC-UX-001 — Autoaprobación activada por defecto
AdminImportModal inicia autoApprove=true. El flujo seguro debería exigir revisión.

### COC-AUTH-001 — Sin autenticación real
No se observa Firebase Auth. Favoritos/historial/colecciones son locales.

### COC-DATA-006 — Favoritos/colecciones en localStorage
No siguen al usuario entre dispositivos y no existe identidad confiable para proteger datos.

### COC-ARCH-001 — Recipe sobrecargado
El producto es un catálogo de videos, pero el dominio principal genera ingredientes, porciones y atributos dietarios aunque la fuente no los proporcione.

### COC-ARCH-002 — Conectores incompletos/simulados
Vimeo, RSS, Website y Manual contienen metadata sintética o capacidades parciales. No debe presentarse metadata inventada como real.

### COC-BUILD-001 — Residuos de AI Studio
Existe public/assets/aistudio y un plugin vite-plugin-aistudio-media.

### COC-OPS-001 — Sin tests/CI visibles
package.json solo declara lint como typecheck; no se observa script test ni workflow en el árbol auditado.

## Orden recomendado
1. Auth + autorización server-side.
2. Eliminar publicación/control administrativo desde cliente.
3. Firestore/persistencia.
4. SSRF + allowlist de plataformas/embeds.
5. Zod + body limits + rate limiting + CORS + security headers.
6. Eliminar fallbacks ficticios y aplicar fail-closed.
7. Separar Video de metadata Recipe y marcar inferencias.
8. Tests + CI.
9. Reintroducir IA solo donde aporte valor y con controles de coste.
